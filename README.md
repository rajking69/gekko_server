## Overview

Initial production foundation for the Gekko Community platform. This phase provides the NestJS application shell, configuration, MongoDB Atlas connection, health endpoint, validation, security headers, CORS, error formatting, and Swagger documentation.

## Tech stack

- NestJS and TypeScript
- MongoDB Atlas with Mongoose
- `@nestjs/config`, `class-validator`, and `class-transformer`
- Swagger and Helmet

## Installation

```bash
npm install
```

Copy `.env.example` to `.env`, then set the real MongoDB connection string.

## Environment variables

| Variable | Description |
| --- | --- |
| `NODE_ENV` | Runtime environment, such as `development` |
| `PORT` | HTTP port, default `5000` |
| `MONGODB_URI` | MongoDB Atlas connection string |
| `FRONTEND_URL` | Allowed frontend origin |

The database defaults to `Team_Gekko` when the URI does not include a database name. A database name already present in the URI is respected.

## Endpoints

- Health: `GET /api/v1/health`
- Swagger: `GET /api/docs`

## Architecture

- `src/config`: environment loading and validation
- `src/database`: isolated asynchronous Mongoose connection
- `src/health`: server health endpoint
- `src/common`: shared response and exception handling
- `src/main.ts`: global middleware, validation, CORS, Helmet, and Swagger

No authentication, users, roles, or business feature modules are included in this phase.
